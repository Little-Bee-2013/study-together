## 这是什么

这里放的是我们学校日常用到的学习资料：模拟测验、参考答案、阅读技巧等等，按**日期**归档，方便大家随时翻出来对答案、查漏补缺。

所有资料都可以直接在网页上打开阅读，看到有用的可以直接复制、截图，或者下载到自己手机上随时看。

**这个仓库会一直更新。** 之后每次发下来的卷子、整理的答案和技巧，都会按日期继续加进来。建议大家**收藏这个页面**，隔一段时间就回来看看有没有新东西。

## 怎么找资料

目录按「**日期 → 科目 → 资料**」三层排列，一层一层点进去就行：

```
20261102/          ← 先点日期
└── 语文/          ← 再点科目
    ├── 初二上期中语文模拟测验.md
    └── ...        ← 就是对应的资料
```

举个例子：想找 11 月 2 日那份语文期中模拟，就点 `20261102` → 点 `语文` → 打开里面的文件。

新资料会不断按这个结构加进去，所以找的时候**先看日期，再看科目**，一般两步就到。

## MD 还是 PDF，怎么选

同一份资料常常有两个版本，打开速度不一样：

| 格式 | 打开速度 | 长什么样 | 建议 |
| :---: | :---: | --- | --- |
| **MD** | **快** | 纯文字，排版朴素，有点丑 | 先点这个，基本秒开 |
| **PDF** | **慢** | 排版完整，和发下来的卷子一样 | 想看得舒服时用它 |

原因很简单：MD 是纯文字，网页直接就把字显示出来了；PDF 是一整个文件包，得先下载完才能看，所以慢。

**所以：先点 MD。** 如果 PDF 点开半天打不开、或者一直在转圈，那就退回上一页点 MD——**虽然丑一点，但内容是一样的，而且快得多。**

## 用之前先看一眼

- **手机上也能看**，建议用浏览器直接打开这个页面，别在微信里点（微信内置浏览器有时打不开文件）。
- 如果 PDF 打不开或者一直转圈，直接点同一份的 MD 版本。
- 资料会不断补充，收藏这个页面，下次直接进来找最新的。

# 最后：给没用过 GitHub 的同学

这一节是**通用说明**，讲清楚 GitHub 是什么、怎么看、怎么操作。看一遍就会，不需要任何基础。

## 一、先搞明白：GitHub 是个什么东西

好多同学第一次点进来会懵——**这网站长得跟小红书、微信完全不一样**。所以先打个比方。

**GitHub 最像一个"公共网盘文件夹"。**

小红书是"刷内容"的：你打开就有人推给你看，你点赞、收藏、评论，内容是一条一条流过去的。

GitHub 不是这样的。它是一个**按文件夹摆东西的地方**，你自己一层一层点进去，想看什么点什么。没有人给你推内容，也没有算法。你现在看到的这个页面，就是某个文件夹的"前言"。

官方文档里有个特别好用的说法：**仓库，你最容易把它想象成一个项目文件夹**。所以对咱们来说：

> **一个"仓库"（Repository）= 一个共享文件夹。**
> 这个文件夹里可以放文件，也可以放子文件夹，子文件夹里再放文件。

就这么简单。你现在就在一个叫 `study-together` 的文件夹里。

### 对照表：GitHub 的功能，等于你熟悉的东西

| GitHub 上的说法 | 大概等于什么 | 在哪 |
| --- | --- | --- |
| 仓库（Repository） | 一个共享文件夹 | 你现在这个页面 |
| 文件列表 | 文件夹里摆着的东西 | 页面正中 |
| README | 文件夹门口的"说明牌" | 就是你现在看的这一页 |
| Star（星标） | 小红书那种**点赞＋收藏**，一步完成 | 页面右上角 |
| Watch（关注） | 微信里的**订阅更新提醒**，像关注公众号 | Star 旁边 |
| Issue（议题） | **留言板 / 评论区**，有话说的地方 | 页面上方标签栏 |
| Pull Request | **投稿**：我改好了，请收下 | 页面上方标签栏 |
| Fork（复刻） | 把别人的文件夹**复制一份到自己名下** | 页面右上角 |
| Commit（提交） | **保存**一下，存个档 | 改文件时出现 |

**最重要的一条好消息：光看资料、光下载资料，你根本不用注册账号。**

官方文档明确写着：**公共存储库可供任何人查看，包括不是 GitHub 用户的人员**。这个仓库是公开的，所以你不登录，一样能点开每一份文件、一样能下载。

## 二、不用注册就能做的事（零基础照做）

打开这个网址就行：

> **https://github.com/Little-Bee-2013/study-together**

### 第 1 步：认页面

进来以后，页面中间那一块**竖着排的一列名字**，就是文件夹里的东西。带小图标的、名字后面跟着斜杠的，是文件夹；名字后面带 `.md`、`.pdf` 的，是文件。

### 第 2 步：进文件夹

直接**点文件夹的名字**。比如点 `20261102`，就进去了；再点 `语文`，又进去一层。

**想退回去**，就点面包屑——就是页面上方那行 `study-together / 20261102 / 语文`，点哪个名字就回到哪一层。跟电脑上点文件夹是一样的。

### 第 3 步：打开文件

- **点 `.md` 文件**：网页直接就把里面的字显示出来了，不用下载，直接能看。
- **点 `.pdf` 文件**：要在网页上的阅读器里打开，或者下载下来用手机自带的软件看。
- 想看**原始内容**，点文件右上角那个下载图标（Raw），浏览器会直接给你原文件。

### 第 4 步：把资料存到自己手机上

有两种存法，按需要选：

**只存一份文件**（比如就要那张卷子）：
点开这个文件 → 右上角找到**下载按钮**（一个向下的箭头）→ 点它，文件就存到手机里了。

**把整个文件夹都存下来**：

1. 先回到仓库的主页面（就是显示所有文件的那一页）。
2. 在文件列表的**上方**，找到那个写着 **Code** 的绿色按钮，点它。
3. 在弹出的框里点 **Download ZIP**。
4. 整个仓库会打包成一个压缩包下载下来，解压后就是一模一样的文件夹结构。

### 第 5 步：看"这个文件是什么时候加的"

每个文件旁边都有一句话，写着它**上次被修改的时间**，还有一个简短的说明。想知道哪份是最新的，看这里就行。

**做到这里，你就已经把 GitHub 当网盘用会了。** 下面全是"注册之后才能干的事"，不看也不影响你用资料。

## 三、想注册一个（可选）

如果你以后想点赞、评论、给这个仓库投个稿，那需要一个账号。注册免费。

1. 打开 **https://github.com**
2. 点右上角的 **Sign up**（注册）
3. 填邮箱、设密码、起一个用户名（英文，像网名一样就行）
4. 做完验证就行

**跟注册小红书差不多。** 起用户名的时候选个好记的，这个用户名以后会跟着你。

## 四、注册之后能做的事

### 1. Star（点星）——相当于点赞加收藏

看到这个仓库觉得有用，就在**页面右上角**找到 **Star** 按钮（一颗星星，旁边写着 Star），点一下。

官方文档里的操作就两步：**进入仓库主页面 → 点右上角的"星标"**。

点完之后星星会亮起来，再点一下是取消。

**点了星有什么好处？** 收藏起来的仓库，以后从**你个人主页的"星标"页**就能一眼找到，不用再翻聊天记录找链接。地址是 `https://github.com/stars`，或者点右上角你自己的头像 → 你的星标。

顺便说一句：**给别人点星也是一种礼貌。** 官方文档里写了，加星标可以表示对维护者工作的赞赏，很多项目的排名也看星星数。所以觉得有用就点一下，作者会看到的。

### 2. Watch（关注）——相当于订阅更新

在 Star 旁边还有一个 **Watch** 按钮。点了它，这个仓库**一有新动静**（比如加了新资料、有人发了评论），你就能收到通知，不用天天自己来看。

Watch 有四个档位，按需要选：

| 档位 | 意思是 |
| --- | --- |
| **All Activity** | 这个仓库发生的所有事都通知我 |
| **Participating and @mentions** | 只通知我参与的、或者点到我的那些（默认） |
| **Releases only** | 只在新版本发布时通知我 |
| **Ignore** | 什么都别通知我 |

**咱们这个仓库，选默认那档就行**——因为资料更新后会说一声，用不着被每条动静都打扰。

### 3. 评论（在哪说话）

**先说一个容易误会的地方：文件页面本身是没有评论框的。**

不是每份资料下面都能评论，这是 GitHub 的设计——**说话的地方统一在"议题"（Issues）区**。

怎么找：

1. 回到仓库的主页面（显示所有文件那一页）。
2. 看页面上方那一排标签，找到 **Issues**，点它。
3. 这里就是**留言板**了。别人发过的话、作者的回复，都按一条一条排在这里。

一句话概括：**想看别人说了什么、想自己说点什么，都去 Issues。**

> 小提醒：如果你想评论的对象是一个**具体文件**，最快的办法是在 Issue 里把文件名写清楚，比如"想问一下 `阅读题技巧.md` 里面第三点是什么意思"。这样作者一看就懂。

### 4. 提建议 / 报告问题（发一条新议题）

发现资料有问题，或者有想问的，可以**开一条新的留言**：

1. 进 **Issues** 标签页。
2. 点绿色的 **New issue** 按钮。
3. 填**标题**（一句话说清楚是什么事，比如"建议补充数学期中答案"）。
4. 在下面的大框里写具体内容（可以说想加什么、哪里看不懂）。
5. 点 **Submit new issue** 提交。

提交完就等着，作者看到会回你。这个功能官方叫**议题**，作用就是跟踪问题、需求或者讨论，说白了就是一个**任务清单加留言板**。

### 5. 一起往里加资料（"共同提交"是怎么回事）

这是 GitHub 最厉害的地方——**不只是作者能加东西，别人也能改，改完还能被"收下"**。官方把这件事叫**拉取请求（Pull Request）**，定义是：**用户提交的对存储库的建议更改，由存储库协作者接受或拒绝。**

用咱们的比方说：**这就是"投稿"。**

投稿有**轻松版**和**正式版**两条路，你挑一条就行。

#### 轻松版：喊一声（推荐第一次用这个）

你自己手上有一份好资料想加进去，但不会操作 GitHub：

**直接开一条 Issue**，标题写"我有一份 XX 想加进来"，正文里说明这是什么资料、怎么发给你。作者看到后自己上传就行。

这条路**完全不用懂技术**，适合所有人。

#### 正式版：自己动手投稿（Fork + Pull Request）

如果你已经会了点，想自己提交，流程是这样：

**第一步：Fork（复刻）。** 在仓库页面右上角点 **Fork**。这一步的意思是：**把别人的这个文件夹，复制一份到你自己的账号名下**。官方定义是"位于你账户中的其他用户存储库的个人副本"。复制过来的这份**完全归你**，你怎么改都不影响原来那个。

**第二步：在你自己的那份里改。**
- 进你的仓库，点开要改的文件。
- 点右上角那支**铅笔图标**（编辑）。
- 改完内容，拉到最下面，点 **Commit changes**（提交更改）。
- 在弹出的框里写一句话说明你改了什么，比如"补充了第三题的答案"，然后再点一次提交。

（"提交"这个词你不用怕，**它在这里就等于"保存"**。官方文档的原话：**在 GitHub 中，已保存的更改称为提交**。）

**第三步：发 Pull request（也就是投稿）。**

1. 点页面上方的 **Pull requests** 标签。
2. 点 **New pull request**。
3. 选好要对比的两个分支（一般保持默认就行）。
4. 看一眼页面上**红色和绿色的对比**——红色是你删掉的内容，绿色是你新加的内容，确认是自己想要的。
5. 点 **Create pull request**，写个标题说明一下，再点一次创建。

**第四步：等作者回复。** 作者会看到你的投稿，如果没问题就会点 **Merge**（合并）——合并之后，你加的东西就正式进到原来的仓库里了，全班同学都能看到。

**如果作者觉得还要改**，会在你的投稿下面留言，或者直接提意见。你就照着重改一次，再提交一遍就行。

#### 附：整个流程的时间线

```
你 Fork 一份  →  在自己那份里改  →  提交保存  →  发 PR 投稿  →  作者审核  →  合并，大家都看到
```

### 6. 万一我改坏了别人的仓库怎么办？

**不可能。** 这是 GitHub 设计上就防住的：

**你 Fork 出来的那一份，是完全独立的另一个副本。** 你在自己那份里删光、改乱，**原仓库一个字都不会变**。只有当你主动发 Pull Request、并且作者点了"合并"之后，你的改动才会进到原仓库。

所以放心大胆地试，不会给谁添麻烦。

## 五、几个同学常问的问题

**Q：我不注册，能不能看和下载？**
能。官方明确说公共存储库任何人都能查看，包括不是 GitHub 用户的人。**注册只是为了能点赞、能留言、能投稿。**

**Q：要不要花钱？**
不要。注册免费，看资料免费，下载免费。

**Q：手机上能用吗？**
能，用手机浏览器打开就行。GitHub 的手机网页版功能和电脑上基本一样，只是按钮小一点。

**Q：为什么我有时候打不开这个网站？**
GitHub 在国内访问偶尔会抽风，这是网络线路的问题，不是你操作错了。**过一会儿再试，或者换个网络（比如手机流量和 WiFi 换一下）通常就好了。**

**Q：它跟小红书、微信最大的区别是什么？**
小红书是"内容推着你走"，微信是"消息推着你走"；**GitHub 是"你自己去文件夹里拿"**。所以第一次会觉得有点冷清、有点找不到北，这是正常的，习惯就好——**它本来就不是用来刷的，是用来放东西和找东西的。**

**Q：我会不会不小心把东西发到网上去？**
不会。**光是看、光是点，什么都不会上传。** 只有你自己动手去"编辑文件并提交"或者"发投稿"，才可能留下痕迹，而且那些都必须是你主动操作的。

## 六、三个小规矩（用起来更舒服）

1. **别人给你开了门，说声谢谢。** 觉得有用就点个 Star，作者会看到。
2. **有话好好说，说清楚。** 提 Issue 的时候，标题写明白是什么事，正文写清具体情况，作者才好处理。
3. **先搜再问。** 想提问题之前，先在 Issues 里翻一翻，也许已经有人问过了。
